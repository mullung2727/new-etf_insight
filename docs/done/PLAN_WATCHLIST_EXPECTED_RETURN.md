# PLAN — Watchlist 기대수익률 점수 전환

## 목표

- 기존 `llm_scores.score`의 급등 원인 명확성 점수를 실제 기대수익과 연결된 점수로 전환한다.
- 한 번에 운영 로직을 교체하지 않고 데이터 감사, 관계 분석, 특징 분석, 청산전략 비교,
  모델 개발, shadow 검증, 운영 전환 순서로 진행한다.
- 각 단계 결과를 검토한 뒤 다음 단계 세부 계획을 갱신한다.

## 연구 코드 관리 원칙

- 일회성 스크립트로 폐기하지 않고 루트 `research/watchlist_expected_return/`에서 관리한다.
- 운영 배치 코드와 분리하되 실제 운영 DB 스키마와 동일한 fixture로 테스트한다.
- 공통 데이터 로딩과 수익률 계산은 이후 단계에서 재사용하거나 확장한다.
- 단계별 기계 판독 결과와 검토용 문서는 `research/watchlist_expected_return/results/`에 생성한다.
- 운영 DB는 연구 코드에서 읽기 전용으로만 연다.

## 단계

### 1단계 — 데이터 품질과 분석 가능 범위 확정

- `watchlist`, `llm_scores`, `intraday_ranking`, `close_bet_orders`, KRX OHLCV의 기간,
  표본 수, 스키마, 결측률을 조사한다.
- 각 watchlist 행의 D일 종가와 D+1~D+5 거래일 OHLCV 연결 가능 여부를 확인한다.
- 실제 주문 표본에서 종가 대비 체결가 차이와 저장된 수수료·세금·실현손익 범위를 확인한다.
- 기존 근거 데이터의 생성시각과 출처시각을 검증할 수 있는지도 감사한다.
- 결과 검토 전에는 2단계로 넘어가지 않는다.

### 2단계 — 기존 점수와 실제 수익 관계 분석

- 기존 점수와 `D 종가 → D+1 시가` 갭 수익률 관계를 우선 분석한다.
- 점수 구간별 평균·중앙값·상승 확률·하락 꼬리·표본 수와 신뢰구간을 비교한다.
- D+1 종가와 D+1~D+5 수익률은 보조 결과로 비교한다.
- 1단계에서 확인된 표본과 신뢰 가능한 필드만 사용한다.

### 3단계 — 다음날 시가 상승 종목 특징 분석

- `D+1 시가 > D 종가`와 거래비용 차감 후 양수인 경우를 각각 분석한다.
- 가격·거래량·거래대금·순위·기존 카테고리·근거 소스 특징을 비교한다.
- 시간순 검증 구간에서 반복되는 특징만 모델 후보로 유지한다.
- LLM은 당시 확인 가능한 텍스트의 구조화 특징만 추출하고 점수를 직접 생성하지 않는다.

### 4단계 — 보유기간과 TP/SL 조합 비교

- 현재 `+5% 익절/-3% 손절, T+1 강제청산`을 기준선으로 둔다.
- 최대 D+5까지 고정 보유와 TP·SL·최대 보유기간 조합을 비교한다.
- 총수익과 비용·슬리피지 차감 순수익을 함께 제시한다.
- 일봉에서 TP와 SL이 같은 날 모두 도달하면 SL 우선을 기본 결과로 하고 TP 우선 결과도 병기한다.
- 평균·중앙 순수익, 승률, 손실 하위 꼬리, 최대낙폭, 자금 회전율을 함께 평가한다.

### 5단계 — 기대수익률 점수 설계

- LangGraph는 뉴스·공시·커뮤니티·시장 데이터 분석을 분기하고 시점이 포함된 구조화 특징을 반환한다.
- 백테스트된 통계 모델이 선택된 청산 정책의 예상 순수익률을 계산한다.
- 시간순 walk-forward 검증으로 미래정보 누출을 차단한다.
- 출력은 예상 순수익률 `expected_net_return`과 학습 구간 내 순위를 변환한 0~100점 `score`다.
- 모델 버전, 입력 기준시각, 보유기간, 청산 정책을 함께 저장한다.

### 6단계 — 별도 저장과 Shadow 검증

- 기존 `llm_scores.score`와 운영 매수 로직은 유지한다.
- shadow 기간에는 별도 JSON에 저장하고, 운영 전환 후에는 신규 점수를 기존 `llm_scores`에 저장한다.
- 실제 주문에는 사용하지 않고 예측 오차와 점수 구간별 실현수익을 누적 비교한다.
- 검토 후 승인된 모델만 운영 전환 후보가 된다.

### 7단계 — 운영 전환

- 승인된 모델 버전만 운영용으로 승격한다.
- 신규 점수 분포와 실현수익을 기준으로 매수 임계값을 다시 정한다.
- 과거 원인 명확성 점수는 유지하고 운영 전환일 이후 생성되는 행부터 상승가능성 점수로 저장한다.

## 단계 게이트

- 각 단계는 코드, 테스트, JSON/Markdown 결과를 완성한 뒤 중단한다.
- 결과와 한계를 이 문서에 요약하고 사용자 검토를 받는다.
- 다음 단계의 가설·입력·판정 기준은 직전 결과를 반영해 확정한다.

## 확정 전제

- 진입 기준가는 watchlist 생성일 D일 종가다.
- 분석 보유 상한은 5거래일이다.
- 목표는 비용 차감 순기대수익 극대화와 손실 위험 제한이다.
- `+5%/-3%`는 현재 청산 조건이다.
- 신규 점수는 기존 점수를 덮어쓰지 않고 별도 저장 후 검증한다.
