# 스윙 후보 3종목 선정 배치 + 체크리스트 검토 설계

> 요약: 매 거래일 19:00, 텔레그램·유튜브·증권사 리포트·high52 후보를 모아 **체크리스트**(Jev 2 + 코드 3 + 참고 2)로 판정.
> 리스크 이벤트 걸리면 탈락, 나머지 4항목 **3단계(0/1/2) 합산** 상위 3종목을 GPT로 요약해 배치 채널로 보낸다.
> 탈락 종목 포함 전 판정을 DB에 매일 쌓는다. 사용자는 원할 때 Claude Code `/pick`으로 심층분석, 결론만 투자노트에 남긴다.
> 보유 관점 1주~1달. 자동매매 아님 — 주문 없음.

상태: 설계 완료, 구현 대기 (2026-09-26). 범위 = 배치까지. `/pick`은 보류.

### 0-2. 체크리스트와 점수

| # | 항목 | 판정 | 0점 | 1점 | 2점 |
|---|---|---|---|---|---|
| 1 | 재료 지속성 | Jev | 없음/일회성 (score < 0.67) | 약함 (0.67~1.33) | 강함 (≥ 1.33) |
| 2 | 리스크 이벤트 | Jev | **점수 없음 — '예' 확률 ≥ 0.5면 탈락** | | |
| 3 | 실적 (최근 분기 영업이익) | 코드 | 적자 | 흑자, 전년 동기 대비 감소 | 흑자, 전년 동기 대비 증가 |
| 4 | 수급 (5일 순매수) | 코드 | 외인·기관 둘 다 순매도 | 하나만 순매수 | 둘 다 순매수 |
| 5 | 차트 (오늘 종가 = 19:00 일괄시세) | 코드 | 20일선 아래 또는 5일 상승 ≥ 30% | 20일선 위, 5일 상승 15~30% | 20일선 위, 5일 상승 < 15% |
| 6 | PER (시총 = D-1) | 참고 | 점수 없음. 값만 표시 (적자면 "적자") | | |
| 7 | 테마 | 참고 | 점수 없음. **상위 후보만** 조회해 소속 테마·테마 수익률·상승/하락 종목 수 표시 | | |

- 총점 = 1+3+4+5 = **0~8점**. 상위 **3종목**
- 동점 → 1번 Jev score 높은 순 → 그래도 같으면 종목코드 오름차순
- 원값(Jev score/확률, 순매수액, 20일선 이격, 5일 상승률, 영업이익)은 점수와 별도로 **전부 저장** (나중에 항목별 검증용)

## 2. 구현 메모

### 2-1. 파이프라인 (LangGraph 노드)

```text
collect      §0-1 소스 4개 → 후보 풀 (종목별 소스 태그)
prefilter    §0-1 1차 컷
judge_code   3·4·5번 점수 + 원값, 6번 PER 참고값 (2번 탈락 종목은 키움 조회 생략)
judge_jev    1·2번 (score/noul 원값 + 단계 변환)
rank         2번 탈락 → 1+3+4+5 합산 → 동점 규칙 → 상위부터 ka10100 정리매매·관리종목 확인하며 3개 채움 → 상위 후보만 7번 테마 조회
summarize    GPT 1회: 3종목 × (소스, 항목 점수, 근거) → 요약문

notify       channel="batch"
```

### 2-3. 결과 DB — `etl/db/swing_pick.sqlite3` (신규)

```sql
CREATE TABLE swing_candidates (
    date_kst      TEXT NOT NULL,
    ticker        TEXT NOT NULL,
    name          TEXT NOT NULL,
    sources       TEXT NOT NULL,     -- JSON 배열: telegram / youtube / report / high52
    trading_value INTEGER,           -- 1차 컷 근거
    -- 원값 (검증용)
    jev_sustain   REAL,              -- 1번 Jev score
    jev_risk      REAL,              -- 2번 Jev noul('예' 확률)
    op_profit     REAL,              -- 3번 최근 분기 영업이익
    op_profit_yoy REAL,              -- 3번 전년 동기 영업이익
    frgn_net_5d   INTEGER,           -- 4번 외인 5일 순매수(금액)
    orgn_net_5d   INTEGER,           -- 4번 기관 5일 순매수(금액)
    ma20_gap      REAL,              -- 5번 종가/20일선 - 1
    ret_5d        REAL,              -- 5번 5일 상승률
    per           REAL,              -- 6번 참고 (적자면 NULL + per_note)
    per_note      TEXT,
    themes        TEXT,              -- 7번 참고: JSON [{name, ret, up, down}]
    -- 점수
    s1 INTEGER, s3 INTEGER, s4 INTEGER, s5 INTEGER,   -- 0/1/2
    risk_out      INTEGER NOT NULL,  -- 2번 탈락 1/0
    total         INTEGER,           -- s1+s3+s4+s5 (탈락도 계산해 둠)
    rank          INTEGER,           -- 최종 순위 (상위 3만 1~3, 나머지 NULL)
    errors        TEXT,              -- JSON {항목: 오류명}
    jev_input_hash TEXT,             -- Jev 입력 묶음 sha1 (재현·중복 확인)
    created_at    TEXT NOT NULL,
    PRIMARY KEY (date_kst, ticker)
);

CREATE TABLE swing_runs (
    date_kst      TEXT PRIMARY KEY,
    n_candidates  INTEGER NOT NULL,
    n_risk_out    INTEGER NOT NULL,
    n_errors      INTEGER NOT NULL,
    jev_input_tokens INTEGER,
    summary       TEXT,              -- GPT 요약문 (실패 시 NULL)
    summary_model TEXT,
    notified      INTEGER NOT NULL,  -- 전송 성공 1/0
    created_at    TEXT NOT NULL
);
```

- 같은 날 재실행: 해당 date_kst 행 교체 (멱등). `etl/docs/DB_SCHEMA.md`에 추가
- 접속은 기존 규약 `wl_sqlite` `connect_rw`/`connect_ro`

## 3. `/pick` 스킬 (사용자 검토) — **보류, 이번 구현 범위 밖**

> 미결: 투자노트에 결론만 vs 결론+항목별 사용자 점수(배치 점수와 비교 가능).


1. 당일(또는 지정일) 결과 DB 로드 → 상위 3 + 차점 몇 개 표시
2. 종목별 항목 점수와 근거를 하나씩 제시, 사용자 확인
3. 심층 조회: kiwoom MCP(차트·호가), 네이버 리서치
4. 사용자 결론 → `create_note` / `add_note_event`로 투자노트 기록 (배치 DB는 수정 안 함)

## 4. 요구사항 → 테스트

| 요구사항 | 테스트 |
|---|---|
| 2번 걸리면 점수 무관 탈락 | 점수 8점 + 2번 확률 0.5 종목 → 상위 3 미포함 |
| 3단계 변환 경계 | Jev score 0.66/0.67/1.32/1.33, 5일 상승 14.9/15/29.9/30% → 기대 단계 |
| PER·테마는 점수 무관 | PER·테마만 다른 두 종목 → 점수·순위 동일 |
| 합산 상위 3 | 점수 다른 5종목 → 상위 3 순서 일치 |
| 동점은 1번 Jev score 순 | 점수 같은 4종목, 1번 score만 다름 → score 높은 3개 |
| 후보 3개 미만 | 통과 2개 → 2개만 출력, 오류 없음 |
| 탈락 종목도 저장 | 탈락 종목 행이 항목별 점수·원값과 함께 DB에 존재 |
| 텔레그램 추가 LLM 0 | collect 노드가 LLM/Jev 호출 안 함 (mock 호출 0회) |
| 1차 컷 | 거래대금 49억 종목 제외, 50억 포함. 스팩·거래정지 제외 |
| 리포트 판정 | 직전보다 목표가 높음 → 통과, 같음/낮음 → 제외, 이력 없음 → 통과 |
| 리포트 직전값 합산 | 직전 리포트가 `report_facts`에만 있음 → 그 목표가와 비교. `parse_status≠ok` 행은 직전값 후보에서 제외 |
| Jev·키움 오류 격리 | 예외 1종목 → 해당 항목 error·0점, 나머지 정상, 보고문에 오류 수 |

## 5. 목적

- 여러 소스 후보를 **같은 체크리스트**로 매일 판정 → 최종 3종목
- 판정 이력 누적 → 나중에 항목별 예측력 검증 (어느 항목이 1주~1달 수익을 가르나)
- 사용자 정성 판단은 투자노트로 분리 → 배치 판정 vs 사용자 판정 성적 비교
- 주의: 지난 Jev 백테스트에서 비슷한 "관심 지속" 질문은 **익일** 예측력 없어 기각 (`PLAN_JEV_CANDIDATE_JUDGE.md`). 이번은 1주~1달이라 별개 — 쌓이는 데이터로 재검증
