# Jev 기반 익일 후보 판단 — 백테스트 + Forward Test 설계

> 요약: 거래대금 Top30 종목의 **텔레그램 원문**을 코드로 모아, Jev(TypeSafe System One)가 1차로 관련 글을 거르고
> 2차로 고정 질문 10개에 답한다. **백테스트는 LLM 없이 Jev만** — Jev 원점수 / 규칙 2개 경로.
> Forward는 여기에 GPT 판정 / GPT 판정(Jev 없이)을 더한 4개 경로를 **서로 못 보게** 독립 실행한다.
> 모든 경로는 무작위 선택·Top30 전체와 같은 기준으로 비교한다.
> 당일 종가 진입(15:10 판단)과 익일 시가 진입(익일 08:00 판단) 두 트랙을 각각 돌린다.
> 과거 구간은 백테스트로 먼저 돌려 표본을 확보하고, 같은 코드로 매일 Forward Test를 쌓는다.

상태: 설계 (구현 전). Jev 미연결 — §10 연결 조치 먼저.

---

## 1. 목적과 검증 질문

실거래가 아니라 **판단 데이터 축적과 예측력 검증**이 목적이다.

1. Jev 질문에 익일 수익률 예측력이 있는가 (무작위·Top30 전체 대비)
2. 규칙과 GPT 판정 중 어느 쪽이 더 안정적인가 (Forward에서만)
3. Jev가 GPT 판정에 기여하는가 (Jev 없는 GPT 판정과 비교, Forward에서만)
4. 어떤 질문이 쓸모 있고 어떤 질문이 버려도 되는가

기존 종가베팅과의 차이: 종가베팅은 LLM 점수 하나로 **당일 종가 진입**. 이 설계는 재료를 **질문 단위로 분해**해
**당일 종가 진입과 익일 시가 진입 두 트랙** 성과를 본다. 검증 대상은 "분해된 재료 판단"이다.

## 3. 결정 필요 (구현 전)

① ~~판단 시각 / 진입 시점~~ → **확정: 두 트랙 모두** (사용자, 2026-09-23). 트랙별 정보 차단선:

| 입력 | 종가 트랙 (as_of = D 15:10) | 시가 트랙 (as_of = D+1 08:00) |
|---|---|---|
| 텔레그램 원문 | `posted_at_utc`→KST ∈ [2거래일 전 00:00, D 15:10] | `posted_at_utc`→KST ∈ [2거래일 전 00:00, D+1 08:00] |
| 후보 Top30 | 백테스트: D 최종 Top60 → 분봉 15:10 누적 거래대금 Top30 / Forward: 15:10 실시간 순위 | D 최종 거래대금 |

- **시각 필터는 `posted_at_utc`(텔레그램 `<time datetime>`, 초 단위)를 KST로 변환해 비교한다.** `date_kst`는 날짜만이라
  차단선 비교에 쓰면 판단 후 글이 섞인다 (`etl/docs/DB_SCHEMA.md` telegram_posts)
- `created_at`(우리 수집 시각)은 2026-01~07 글이 2026-08-26 일괄 소급이라 백테스트 가용성 판정에 못 쓴다.
  Forward에서는 수집 지연이 곧 누락이므로 **판단 직전에 수집을 1회 돌린다** (P6)
- 글 수정: 재수집 시 최신 본문으로 덮어쓴다(`updated_at > created_at` 23,539행, 본문 변경 여부 기록 없음). 수정본 누수 가능.
  **트랙과 무관한 문제**라 두 트랙 모두 백테스트는 선별용, 유효성 판정은 Forward (§9-4).
  수정 빈도 측정: Forward 수집 시 `posts.text_hash` 저장 → 이후 재수집 본문 해시와 비교해 변경 비율 집계. 무시할 수준이면 백테스트 지위 재논의
- 텔레그램만 쓰므로 공시·리서치의 "날짜만 있고 시각 없음" 문제는 v1에서 사라진다 (소스 추가 시 재검토)
- **종가 트랙 후보 선정 편향**: D 최종 거래대금을 쓰면 15:10~15:30을 미리 안다. 완화 = 최종 Top60을 넓게 뽑고
  분봉(`minute_bar_store.load_bars`)으로 15:10까지 누적 거래대금 Top30을 다시 고른다. 분봉 스키마에 거래대금이 없어
  (OHLCV만, `minute_bar_store.py` `_SCHEMA`) **Σ(분봉 close × volume) 추정치**로 순위를 낸다 — 근사. 남는 편향은 마지막 20분에
  Top60 밖에서 진입한 종목뿐이지만 0은 아니다 → **종가 트랙 백테스트는 탐색 결과로만 쓰고 유효성 판정은 Forward로 한다** (시가 트랙도 글 수정 누수로 동일, 위 항목).
  Forward 순위 겹침률은 참고 자료이지 백테스트 편향의 보정값이 아니다
- 종가 트랙 시간 예산: 15:10 수집 → 판단 → 15:19 완료. 텔레그램 수집 + Jev 2회 수 초 + GPT 판정(C·D, 8병렬 약 40초 × 3회).
  넘치면 판정 반복(3회 중앙값)을 1회로 줄인다 — P6에서 실측
- **종가 트랙 진입 방식**: Forward는 모의 기록이라 진입가 = D 종가(종가 단일가 체결가). 실매매 전환 시 기존 종가베팅
  (`run_close_bet.py`, 주문 마감 15:20:00) 방식으로 15:20 전에 주문해 종가 단일가에 참여한다

② ~~GPT 모델~~ → **확정: `gpt-5.6-luna`** (사용자, 2026-09-23). Forward C·D 경로에서만 쓴다.

③ ~~백테스트 구간~~ → **확정: 2026-01-02 ~ 2026-09-22 (약 180거래일)** (사용자, 2026-09-23).
텔레그램 원문 적재가 2026-01-01부터라서 (월 9~12천 건, awake 제외). 소급 수집은 하지 않는다.

## 4. 파이프라인

```text
D일 거래대금 Top30 (krx_ohlcv)          ← 코드
  ↓ 제외 가드 (스팩·정지·정리매매)         ← 코드
  ↓
텔레그램 후보 글 (트랙별 as_of, §3 ① 표)   ← 코드, LLM 없음
  telegram_posts 원문, 종목명 문자열 포함 글, awake_realtimeCheck 제외
  ↓
Jev 1차: 글마다 noul "이 글은 종목A 자체를 다룬다"   ← 오탐 22.6% 제거 (BACKTEST_DATA §4d 함정 2)
  ↓ noul ≥ 0.5 만 통과
코드: 익명화 → 당일/과거 섹션 분리 → 최신순 3,000토큰 자르기 → state_text
  ↓
Jev 2차: 질문 10개 (1회 호출/종목)
  ↓
┌──────────────┬──────────────┬─────────────────────┬──────────────────────┐
│ A Jev 원점수  │ B 규칙        │ C GPT 판정 (Forward) │ D GPT 판정 (Forward)  │
│ 가중합 순위   │ 고정 임계값   │ state_text + Jev 답  │ state_text 만         │
└──────────────┴──────────────┴─────────────────────┴──────────────────────┘
  + 기준 E: Top30 전체 동일가중   + 기준 F: 무작위 3종목 (1,000회 placebo)
  ↓ 각자 저장 (서로의 결과를 입력으로 받지 않음)
D+1 성과 계산 → 평가
```

**백테스트와 Forward는 같은 state 생성 코드를 쓴다.** 운영 텔레그램 요약 테이블(`telegram_stock_insights`)은
과거 이력이 없으므로 쓰지 않고, 양쪽 다 원문 `telegram_posts`에서 출발한다. 다른 입력을 쓰면 두 결과를 비교할 수 없다.
Forward의 C·D(GPT)도 같은 `state_text`를 받는다 — 입력 차이로 경로 비교가 오염되지 않게.

## 5. State 설계 (GPT 요약 없음, 코드 + Jev 1차 필터)

### 5-1. 후보 글 조회 (코드)

- `telegram_posts` 에서 `channel != 'awake_realtimeCheck'` AND 트랙 구간 AND `text LIKE '%종목명%'`
- 종목명: `stock_names`는 종목코드당 이름 1개를 덮어쓰는 캐시(`etl/scripts/stock_names.py` `upsert_names`, INSERT OR REPLACE)라
  과거 이름을 못 준다. → 백테스트 구간에서 KRX 일별 조회(ISU_NM)로 **사명 변경 종목 목록**을 한 번 만들고,
  그 종목은 옛 이름·새 이름 모두 검색어로 쓴다. 익명화도 두 이름 모두 치환
- 같은 글이 여러 채널에 복제된 경우 본문 앞 200자 해시로 중복 제거

### 5-2. Jev 1차 필터 (글마다)

- 질문 1개 noul: instructions = "이 글의 주제가 종목A 자체다. 다른 회사 글에 발행 증권사·지수 구성종목·단어 일부로만 등장하면 아니다"
- state = 글 1개 (익명화 후). 글이 많아도 1,200 요청/분 한도 안 (Top30 × 평균 수 건)
- `noul ≥ 0.5` 통과. `0.35~0.65` 비율을 품질 지표로 저장 (애매 판정이 많으면 질문 문구 수정)
- P1 검수 2종 (5거래일):
  - 정밀도: 이름 포함 후보 글 무작위 100건 → 1차 필터 판정이 맞는지 (오탐·잘못 버림)
  - 재현율: 이름 **미포함** 글 무작위 100건 → 약칭(삼전 등)·영문명·옛 이름으로 그날 Top30 종목을 다루는 글 비율.
    이름 포함 검색만 검수하면 이 누락은 측정되지 않는다. 비율이 크면 약칭 사전 추가 검토

### 5-3. state_text 조립 (코드)

- **익명화**: 대상 종목명·티커 → `종목A`. 글에 나오는 다른 Top30 종목명 → `종목B/C…` (같은 날 같은 매핑). §9-1 누수 대응
- **기준일 = 신호일 D (두 트랙 공통)**. "오늘"이라는 말은 state·질문 어디에도 쓰지 않는다 (시가 트랙은 판단일이 D+1이라 엇갈림)
- **섹션 분리** (게시 시각, 코드): Jev는 날짜 비교가 약하다(문서 jaggedness 5번)
  - `[신호일]` = D 00:00 ~ min(as_of, D 15:30)
  - `[신호일 장마감 후]` = D 15:30 ~ D+1 08:00 (시가 트랙만)
  - `[이전 2일]` = 2거래일 전 00:00 ~ D 00:00 (달력 D-2면 월요일에 금요일이 빠짐, 사이 주말·휴일 글 포함)
- **길이 상한**: 섹션별 최신순, 합계 3,000토큰. 관련 없는 내용이 많을수록 정확도 하락(문서 7번)
- **가격 문장**: 신호일 등락률을 구간 문장("신호일 +10~20% 상승")으로 맨 앞에 1줄. 모든 경로에 동일. Jev는 숫자 판단이 약하다(문서 3·4번)
  - 종가 트랙: **D 15:10 분봉 close ÷ D-1 종가** (D 종가 금지 — 쓰면 미래 정보)
  - 시가 트랙: D 종가 ÷ D-1 종가
  - 구간 경계: −10% 미만 / −10~0 / 0~+5 / +5~+10 / +10~+20 / +20% 이상 (사전 고정)
- **글 0건 종목**: state = 가격 문장 + "관련 글 없음". Jev에 그대로 보낸다 (재료 없음도 정보). `n_posts=0` 기록

### 5-4. 품질 지표 (종목·일마다 저장)

`n_candidates / n_passed / n_ambiguous / n_today / n_past / truncated(bool)`.
- 글 0건 종목 비율이 50%를 넘으면 텔레그램만으로는 부족 → 뉴스 헤드라인 추가 검토 (v2)
- 채널 성격상 증권사 리포트 요약이 대부분이라 답이 한쪽으로 몰릴 위험 (BACKTEST_DATA §4d 분산 부재) → §6 분산 검사로 조기 판정

## 6. Jev 질문 v2 (10개, 영역당 목적 1개) — 2026-09-23 개정

규칙: 한 질문에 판단 하나, 부정문 금지, 날짜·숫자 계산 요구 금지.

- q2에 산업·매크로 추가 (공급부족·데이터센터 투자·원자재·환율이 수급·기타에 섞임)

- 삭제: 과열 서술 — 가격 데이터로 재는 게 맞고, 신호일 글은 주가가 움직여서 쓰인 경우가 많다(역인과)

- 중복 판단은 사전 고민 대신 데이터로: 백테스트 후 질문 간 순위상관 |ρ| > 0.7 쌍은 하나 제거
- **분산 부재 검사**: 한 답이 85% 이상 몰리는 질문은 정보가 없다 → 제거 (텔레그램 정성 팩터 실패 원인, BACKTEST_DATA §4d)

## 7. 판단 경로 (입력 격리)

| 경로 | 입력 | 출력 | 선택 |
|---|---|---|---|
| A Jev 원점수 | Jev 답 | `jev_score` = (q1,q3,q8,q9,q11 의 `score/2`) + (q5 의 `noul`) − (q4,q10 의 `noul`). 동일가중, 사전 고정. q2(choice)·q6은 점수에 안 넣고 분석용 | 상위 3 |
| B 규칙 | Jev 답 | BUY ⇔ q1.score ≥ 1.0 AND q11.score ≥ 0.5 AND q10.noul < 0.3 (v2. v1은 q1 ≥ 1.5 + 후속·테마 조건 → 5일 150종목 BUY 0건) | BUY 중 jev_score 상위 3 |
| C GPT 판정 (Forward만) | state_text + Jev 답 | BUY_CANDIDATE / WATCH / SKIP + confidence(0~1) + 이유 | BUY 중 confidence 상위 3 |
| D GPT 판정(Jev 없음, Forward만) | state_text만 | 같음 | 같음 |
| G 등락률 순위 | 가격 문장과 같은 시점 등락률 | Top30 중 등락률 상위 3 | 상위 3 |
| H 언급량 순위 | Jev 1차 통과 글 수 (`n_passed`) | Top30 중 글 수 상위 3 (동률은 등락률 순) | 상위 3 |
| I 글 섞기 placebo | 같은 날·같은 가격 구간 종목끼리 **글 섹션만 무작위로 맞바꾼** state → 같은 10문항 → A·B와 같은 식 (I_A·I_B) | A·B와 같음 | A·B와 같음 |
| E 기준 | — | Top30 전체 (가드 통과분) | 전부 |
| F placebo | — | 조합마다 Top30에서 무작위 추출 × 1,000회, 4개 조합 최댓값 분포 (§9-3) | — |

- **비교군의 목적**: 신호일 글은 주가가 움직였기 때문에 쓰인 경우가 많다(역인과, BACKTEST_DATA §4d 함정 3).
  A·B가 이겨도 글 내용 판단 덕인지 가격·언급량 덕인지 모른다.
  - G: 가격만의 효과
  - H: 글이 **있다는 사실·양**의 효과
  - I: 가격 구간·글 양은 비슷한데 **내용이 그 종목 것이 아님** → A·B가 I를 이겨야 "내용 판단" 효과. 비용: Jev 2차 호출 종목·일당 1회 추가
  - 글 없는 종목만 있는 가격 구간은 맞바꿀 상대가 없음 → 그 종목은 I에서 원래 state 유지, 건수 기록
- 가격 문장만 넣은 Jev(구 A0·B0)는 뺐다. 글이 없으면 "자료에 원인이 적혀 있다"류 질문이 당연히 낮게 나와 차이가 "글 유무"로 환원된다 — H가 같은 역할을 더 단순하게 한다
- G·H·I는 비교군이다 — 성공 판정 대상(§9-4의 4개 조합)에 넣지 않는다

- **Jev 응답 형식** (docs.typesafe.ai 확인):
  - score: `score` = 등급번호 × 확률의 합 (예: 0×0.0 + 1×0.57 + 2×0.43 = **1.43**, 소수). 등급명이 오지 않는다 → 규칙은 숫자 임계값으로만 쓴다.
    3등급(0~2) 기준 임계값: "명시됨/강함/큼" = score ≥ 1.5, "약함 이상" = ≥ 0.5
  - choice: `choice`, `probabilities`, `confidence`
  - noul: **`noul`(예일 확률 0~1) 하나뿐, confidence 없음**
- **불명 처리 게이트**: score·choice는 `confidence < 0.5`, noul은 `0.35 ≤ noul ≤ 0.65`면 불명.
  불명 답은 A에서 0으로, B에서 해당 조건 불충족으로 본다
- C·D 프롬프트에는 A·B 결과를 넣지 않는다 — 테스트로 강제 (§12 T3)
- GPT는 temperature 최저, 같은 입력 3회 중앙값. 순서 SKIP < WATCH < BUY_CANDIDATE, 중앙값 판정의 confidence·이유를 통째로 채택.
  `median_judgement`(A~E 등급 전용)는 못 쓰므로 새로 작성 (몇 줄)

## 9. 백테스트 설계

### 9-1. 누수 위험과 대응

| 위험 | 대응 |
|---|---|
| Jev가 사전학습으로 그 종목의 이후 주가를 앎 | 2차 state는 익명화. 1차 필터는 판단이 아니라 관련성만 봐서 영향 작음. 백테스트 성과가 Forward보다 크게 좋으면 누수 의심 |
| 텔레그램 글이 as_of 이후 것 섞임 | `posted_at_utc`→KST ≤ as_of 코드 필터 (T1). `date_kst` 비교 금지 |
| 텔레그램 글 사후 수정 | 막을 수 없음 — 한계로 명시 |
| 종가 트랙 Top30 선정 | Top60 → 분봉 15:10 누적 거래대금 Top30으로 완화. 잔여 편향 있음 → 종가 트랙 백테스트는 탐색용 |
| 글 사후 수정 (두 트랙 공통) | 막을 수 없음 → 두 트랙 모두 백테스트는 선별용, 판정은 Forward. 수정 빈도는 Forward에서 측정 |

| 종목명 문자열 매칭 오탐(22.6%) | Jev 1차 필터 noul < 0.5 삭제 |
| 일봉 당일값 조인 | 거래대금 Top30은 D일 값으로 정의상 정당. 나머지 특징은 전부 D일까지 |

### 9-2. 구간과 비용

- 구간: 2026-01-02 ~ 2026-09-22, 약 180거래일 × 30 = 5,400 종목·일 (트랙당)
- 경로: 백테스트는 A·B + 비교군 G·H·I·E·F (LLM 0)
- 시간·비용: 텔레그램은 로컬 DB 조회, Jev 호출은 1,200 요청/분 한도가 병목. 1차(글 수) + 2차(종목·일 × 2트랙) ≈ 수만 요청 → 1시간 안팎.
  Jev 토큰 합계 수천만 이하 ≈ $2 미만
- 트랙은 따로 평가한다. 같은 종목·날이 두 트랙에 다 나와도 합치지 않는다
- 멱등: `(run_id, date, ticker)` 존재 시 건너뜀. 중간에 끊겨도 이어서

### 9-3. 평가 (walk-forward + placebo)

- 학습 구간 2026-01 ~ 05 (약 100거래일) / 검증 구간 2026-06 ~ 09 (약 80거래일). **질문 선별·가중치 변경은 학습 구간에서만**, 검증 구간은 한 번만 본다
- 전반·후반 둘 다 양수 같은 분할 통과는 판정 기준으로 쓰지 않는다 (둘 다 in-sample)
- 지표 (일별 가중, 사이즈 중립 초과): 선택 종목 수, NO-TRADE 비율, 평균, 승률, Profit Factor, MDD
- 벤치마크: 전날 시총으로 구간 배정(룩어헤드 차단), 구간별 동일가중 평균을 **트랙과 같은 구간**으로 계산해 뺀다.
  종가 트랙 = 종가→D+1 시가 / 종가→D+1 09:30 / 종가→D+1 종가, 시가 트랙 = D+1 시가→09:30 / 시가→종가.
  09:30 벤치마크는 분봉이 Top30 거래량 종목뿐이라 전종목 계산 불가 → 09:30 지표는 E(Top30 전체) 대비만 본다
- 순서: 0.35% 비용 차감 후 일별 평균 초과 ≤ 0 이면 t 안 본다 → > 0 이면 **다중비교 보정 placebo** 판정
- **다중비교 보정 placebo (max 통계량)**: 백테스트 조합은 2트랙 × A·B = 4개. placebo 1회 = 조합마다 그날 Top30에서
  무작위 3개(해당 조합의 일별 선택 수와 같은 수) → 4개 조합 각각 일별 평균 초과 계산 → **그중 최댓값** 1개 기록.
  1,000회 반복한 최댓값 분포의 95퍼센타일을 넘어야 통과. 여러 조합을 시도한 효과가 기준에 반영된다.
  연산: 이미 계산된 수익률 배열에서 무작위 추출만 하므로 수 초 (Jev 재호출 없음)
- 질문 기여: 질문별 등급 구간 간 평균 초과수익 차이. 무작위 가짜 질문(값 셔플) 100회와 비교
- **가격 통제 비교**: 가격 구간(§5-3 6구간) 안에서 `jev_score` 상위 절반 vs 하위 절반의 일별 초과수익 차이를 구간별로 내고 평균.
  가격 구간을 고정해도 차이가 남아야 "글 판단"의 효과로 본다

### 9-4. 성공 기준 (사전 고정)

조합(트랙 × 경로)별로 **검증 구간**에서 ① 0.35% 비용 차감 후 일별 평균 초과 > 0, ② max 통계량 placebo 95퍼센타일 초과 (§9-3),
③ E(Top30 전체) 초과, ④ **G(등락률)·H(언급량)·같은 경로의 I(글 섞기, A→I_A, B→I_B) 모두 초과**, ⑤ 가격 통제 비교(§9-3) 차이 > 0.
다섯 다 만족하는 조합만 Forward에서 추적 대상. ①~③만 통과하고 ④·⑤ 실패면 "가격·언급량 효과"로 판정, Jev 재료 판단의 성과로 보지 않는다.
- **백테스트 통과는 두 트랙 모두 "선별 통과"일 뿐이다.** 유효 판정은 Forward에서 같은 기준으로.
  이유: 글 사후 수정 누수(두 트랙 공통, §3 ①), 종가 트랙은 후보 선정 편향 추가
- 텔레그램 정성 정보는 과거 실측에서 예측력이 없었다 (BACKTEST_DATA §4d) → 기준 완화 금지
- 통과 조합이 없으면 질문 세트 v3 설계 후 재실험 (검증 구간 재사용 금지 → Forward로만 검증).
