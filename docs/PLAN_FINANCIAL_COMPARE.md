# 재무제표 다기간 비교 개편 계획

## 한 줄 요약
종목 선택 시 DART 두 API(`fnlttSinglAcntAll` 금액 + `fnlttSinglIndx` 비율)를 호출해 **여러 기간을 한 표에 나란히** 보여주는 비교 뷰로 교체. v1은 **DB 저장 없이 매번 API 호출**, 연간 5년 고정, 차트·토글 없는 표 한 장 — 가장 단순한 형태로 먼저 띄우고 결과를 보며 다음 단계를 계획한다.

---

## 이 계획의 목적 (가장 중요)

**일단 심플하게 만들어 화면으로 확인하는 것.** 최종 그림(분기/연간 토글, 기간 수 조절, 캐시, 장기 추세, 비율 다분류)은 아직 모호하고 장황하다. 그래서 v1은 의도적으로 기능을 깎아내고, 동작하는 결과물을 먼저 본 뒤 다음 단계를 정한다.

- v1 성공 기준 = "종목 고르면 다기간 금액·비율이 한 표에 뜬다." 그 이상 아님.
- 완성도·확장성·성능 최적화는 v1 목표 **아님**. 뼈대만 맞추고 나머지는 미룬다.

---

## 배경: 무엇을 극복하나

| 현재 | 문제 |
|------|------|
| 단일 기간 조회 (`연도+보고서+연결/별도` 4개 수동 선택) | 종목마다 데이터 시작연도·연결유무가 달라, **조회 전엔 무엇이 있는지 모름** → 빈 결과 낚시질 |
| 한 번에 한 기간만 표시 | 추세·비교 불가 |
| 비율을 직접 계산하려면 계정과목이 기업마다 달라 매핑이 깨짐 | 자체 계산 비현실적 |

**핵심 통찰:** 비율은 직접 계산하지 않고 DART 공식 지표 API(`fnlttSinglIndx`, 연결/별도 구분 없음)를 그대로 쓴다. 금액만 `fnlttSinglAcntAll`로 가져온다.

## 두 API 역할 분리

| 용도 | API | fs_div | 이력 범위 | 비고 |
|------|-----|--------|-----------|------|
| 절대금액 (매출·영업이익·자산…) | `fnlttSinglAcntAll` | **있음** (CFS/OFS) | 수년 | account_id로 계정 추출, 연간 reprt_code=`11011` |
| 비율 (영업이익률·ROE·부채비율…) | `fnlttSinglIndx` | **없음** | **2023Q3+** | idx_cl_code 분류별 호출 |

**이력 비대칭:** 비율은 2023Q3부터만 존재 → 표에서 2023 이전 비율 칸은 `—`로 정직하게 비움.

**비율 → idx_cl_code 분류 매핑** (2026-06-10 실호출로 확정):

| 비율 | 처리 | idx_cl_code | idx_code |
|------|------|-------------|----------|
| 영업이익률 | **금액 계산** (opProfit÷revenue×100) | — | — |
| ROE | DART Indx | M210000 (수익성지표) | M211550 |
| 부채비율 | DART Indx | M220000 (안정성지표) | M221100 |
| 매출증가율 | DART Indx | M230000 (성장성지표) | M231000 |

→ 연도당 Indx 호출 3회 (M210000·M220000·M230000), 영업이익률은 M210000에 없어 금액 행 값으로 직접 계산.

## v1 범위

### 포함
- 기존 `SearchBar`(종목 자동완성) **그대로 재사용**
- **연간 5년 고정**, 기간 수 조절 UI 없음. 끝 연도 = 기준 연도(아래 fs_div 판별에서 확정된 연도), 거기서 5년 역산
- fs_div = **연결 우선 자동** (선택 UI 없음). 판별 규칙:
  1. `현재연도 - 1`부터 시작 (사업보고서는 이듬해 3월 제출이라 연초엔 직전 연도가 없을 수 있음)
  2. 해당 연도 CFS 시도 → `013`이면 OFS 시도
  3. 둘 다 `013`이면 보고서 자체 미제출로 보고 한 해 내려서 2번부터 재시도 (최대 2회)
  4. 성공한 연도 = 기준 연도, 성공한 fs_div를 전 연도에 재사용
  - ※ `013`은 "연결 없음"과 "보고서 미제출" 둘 다 의미 → 위 단계적 강등으로 구분
  - ※ 연결 전환 기업은 과거 연도 CFS가 `013`일 수 있음 → 해당 열은 `—`로 비움 (v1은 연도별 fs_div 폴백 안 함)
- 금액 6행 고정: 매출액 · 영업이익 · 당기순이익 · 자산총계 · 부채총계 · 자본총계
- 비율 4행 고정: 영업이익률 · ROE · 부채비율 · 매출증가율
- 표 한 장 (행=항목, 열=연도). 2023 이전 비율 칸 `—`
- **DB 저장 없음 — 매번 DART 호출** (캐시는 다음 단계)

### 제외 (다음 단계 후보)
분기/연간 토글 · 기간 수 조절 · DuckDB 캐시 · 차트 · 비율 4분류 전체 · 금액 항목 커스텀 · 공시목록(`list.json`) 사전조회 · 장기 이력

## 백엔드 흐름

신규 route: `/api/financial/compare?corp_code=<8자리>&years=5`

```
1. fs_div + 기준 연도 결정: 위 판별 규칙 (CFS→OFS→연도 강등). 성공한 호출 결과는 금액 데이터로 재사용
2. 금액: 각 연도 fnlttSinglAcntAll 호출 (reprt_code=11011, 5회) → 6개 account_id 추출
3. 비율: 2023~ 각 연도 × 3개 idx_cl_code 호출 (3년 기준 9회) → 4개 idx 추출
4. 병합 반환:
   { corpName, fsDiv, periods:[2021..2025],
     rows:[ {label:"매출액", type:"amount", values:[...]},
            {label:"영업이익률", type:"ratio", values:[null,null,12.3,...]} ] }
* 호출은 병렬. 캐시 없으니 매 요청 실호출 (금액 5 + 비율 9 ≈ 14회).
```

**구현 노트:**
- 기존 `fetchFinancial`(`lib/dart.ts`)은 status ≠ 000이면 무조건 throw → fs_div 판별은 `013`을 값으로 받아야 하므로 내부 `fetchAcntRaw` 헬퍼(throw 없음)로 분리.
- **CIS 폴백:** 포괄손익계산서만 제출하는 기업(단일 포괄손익계산서 방식)은 IS 계정(`ifrs-full_Revenue` 등)이 `sj_div=CIS`에만 존재. `extractAmount`에서 IS 검색 실패 시 CIS 재시도. M83 실호출로 확인.
