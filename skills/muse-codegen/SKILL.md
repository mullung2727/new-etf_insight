# Muse 코드 작성·검수

## 역할 분담

- 코드 작성·수정은 항상 Muse가 맡는다. 한 줄 수정도 호출 에이전트가 직접 Edit하지 않는다.
- 호출 에이전트(Claude 또는 Codex)는 명세 작성, 코드 검수, 테스트·실행·검증을 직접 맡는다. 별도 리뷰 에이전트는 쓰지 않는다.
- Muse는 파일 작성만 맡는다. 명령 실행·코드 실행·외부 도구 호출을 맡기지 않는다.
- 문서·스킬·프로젝트 지침 편집은 호출 에이전트가 직접 수행할 수 있다.

## 명세와 호출

1. `README.md`, `AGENTS.md`, 해당 작업의 필수 스킬·설계문서를 먼저 읽는다. 백테스트 작업은 `research/BACKTEST_DATA.md`도 읽는다.
2. 명세 파일에 대상 파일의 정확한 경로, 변경 범위, 필요한 기존 코드·데이터 구조, 완료 조건을 적는다. 필요한 맥락은 명세에 제공한다.
3. 명세에 **“명령 실행 금지, 파일만 작성. 테스트·실행·검증은 호출 에이전트가 담당한다.”**를 반드시 넣는다. 요청하지 않은 파일·경로는 만들지 않도록 명시한다.
4. 프로젝트 루트를 작업 폴더로 하여 Bash/Git Bash에서 실행한다. 긴 명세는 인자에 직접 넣지 않고 `--prompt-file`로 전달한다.

```bash
muse.cmd exec --prompt-file <명세.md> < /dev/null
```

- 백그라운드 실행 시에도 `< /dev/null`을 유지한다. stdin 대기를 방지한다.
- Muse의 쓰기 범위는 실행 폴더(workspace root) 안이다. 밖의 git worktree 등 파일을 바꿔야 하면 repo 안 `research/private/...`에 초안을 작성하게 하고 호출 에이전트가 검수 후 대상 경로로 복사한다.
- Muse가 실패하면 직접 코드 작성으로 넘어가지 말고 즉시 사용자에게 알린다.
- 멈춘 것 같으면 `~/.local/share/muse/local-tracing/bootstrap/cli-*.log` 끝부분에서 `approval.requested`를 확인한다. 셸 명령을 시도하면 승인 대기로 멈출 수 있다.

## 직접 검수·검증

- diff에서 요청 범위와 파일 위치를 확인한다. 테스트를 루트 `tests/` 등 엉뚱한 곳에 만들지 않았는지 확인한다.
- 관련 테스트를 실제 실행하고 변경에 관련된 모든 모듈의 import를 확인한다. 검수에서 발견한 수정도 Muse에 다시 맡긴다.
- 설계문서가 있으면 항목별로 `항목 → 파일:줄 → 테스트`를 대조하고, 없음·다름·테스트없음을 표시해 보고한다.
- 직접 코드 수정이 발생했다면 보고와 기존 progress 파일에 “직접 수정”으로 구분한다. 실패 시 직접 작성하는 우회책으로 사용하지 않는다.

작업에 해당하는 검수 항목만 적용한다.

- 백테스트·전략: 판단 시각 이후 정보 사용, 정지·권리락·상한가·분할보정·스팩 가드, 일별 가중 평균, 미처리 행의 그룹 오염. 일봉·분봉 계산은 각각 기존 `research/backtest_daily`, `research/backtest_minute`를 사용한다.
- 데이터 적재: 멱등성, 부분 적재 감지, 미국 ET·서머타임/KST, 휴장일, API 한도·키 노출, 삭제·덮어쓰기 범위.
- 실매매·운영: 실패 시 주문 금지, 중복·초과 주문, 같은 계좌 타전략 보유분 매도 금지, 주문 시간창, 오류 알림. 코드 줄 단위 근거로 확인한다.
